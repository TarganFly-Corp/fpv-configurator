# Технічне завдання: FPV Configurator

Версія 1.0 (ЛР2). Документ містить лише функціональні вимоги.

## 1. Призначення системи

FPV Configurator допомагає зібрати FPV-дрон з окремих комплектуючих так само, як конфігуратор ПК допомагає зібрати комп'ютер. Користувач обирає деталі з каталогу, система перевіряє, чи вони сумісні, і рахує ціну та вагу збірки.

Крім восьми стандартних видів деталей, будь-який користувач може описати власну категорію (наприклад, приймач керування, GPS-модуль, підвіс камери) з власним набором параметрів і додати деталі цієї категорії.

## 2. Користувачі

| Користувач | Що робить у системі |
|---|---|
| Пілот (збирач) | Переглядає каталог, складає збірку, бачить помилки сумісності, ціну і вагу |
| Автор каталогу | Додає деталі стандартних категорій і створює власні категорії та деталі |

## 3. Функціональні вимоги

### 3.1 Каталог і модель деталей (віха M1, ЛР2)

| Код | Вимога |
|---|---|
| ФВ-01 | Система має вісім стандартних категорій: рама, польотний контролер, ESC, мотор, пропелер, камера, відеопередавач, батарея |
| ФВ-02 | Кожна деталь має спільні дані: Id, назва, виробник, ціна (грн), вага (г), ознака наявності |
| ФВ-03 | Параметри деталі задаються схемою категорії. Для кожного параметра схема зберігає ключ, назву, тип значення (текст, ціле число, дробове число, так/ні, вибір зі списку), одиниці виміру, обов'язковість, мінімум і максимум або список дозволених значень |
| ФВ-04 | Під час створення деталі система перевіряє всі параметри за схемою і повідомляє про кожну помилку окремо: пропущений обов'язковий параметр, неправильний тип, вихід за межі, значення не зі списку, зайвий параметр, якого немає в схемі |
| ФВ-05 | Користувач може створити власну категорію з довільним набором параметрів. Ключ категорії має бути унікальним у реєстрі, регістр літер не враховується |
| ФВ-06 | Користувач може створити деталь власної категорії. Така деталь працює через той самий інтерфейс IComponent, що й стандартні |
| ФВ-07 | Нові категорії і деталі можна завантажити з файлу JSON без зміни і перекомпіляції коду |
| ФВ-08 | Id деталей в одному файлі каталогу мають бути унікальними. Повторний Id є помилкою файлу |
| ФВ-09 | Для кожної деталі система показує характеристики у вигляді «назва: значення одиниці» |
| ФВ-10 | Розробник може підключити для категорії власний клас деталі (фабричний метод). Якщо класу немає, використовується універсальна користувацька деталь |

### 3.2 Збірка і сумісність (віха M3, ЛР4)

| Код | Вимога |
|---|---|
| ФВ-11 | Користувач додає деталі у збірку і видаляє їх. Збірка містить одну раму, один польотний контролер, один ESC, чотири мотори, чотири пропелери, одну камеру, один відеопередавач, одну батарею і будь-яку кількість користувацьких деталей |
| ФВ-12 | Система перевіряє сумісність набором незалежних правил (ICompatibilityRule): кріплення стеку рами, контролера і ESC; діаметр пропелера не більший за допустимий для рами; кількість банок батареї входить у діапазон моторів, ESC і контролера; відеосистема камери збігається з відеосистемою передавача |
| ФВ-13 | Нові правила сумісності додаються окремими класами без зміни наявних |
| ФВ-14 | Система рахує загальну ціну і загальну вагу збірки |

### 3.3 Збереження і інтерфейс (віхи M4, M5)

| Код | Вимога |
|---|---|
| ФВ-15 | Збірку можна зберегти і відкрити знову через інтерфейс сховища. У тестах сховище замінюється мок-об'єктом (ЛР5) |
| ФВ-16 | Веб-інтерфейс на Blazor: каталог з фільтром за категорією, сторінка збірки, форма створення власної категорії і деталі (обсяг погоджується з викладачем) |

## 5. Модульна архітектура (коротко)

1. Core описує, що таке параметр (ParameterDefinition), категорія (ComponentCategory), реєстр категорій (ICategoryRegistry), фабрика деталей (IComponentFactory) і правило сумісності (ICompatibilityRule).
2. Components містить вісім стандартних класів і універсальний клас CustomComponent для будь-якої користувацької категорії.
3. Catalog містить реалізації реєстру і фабрики, схеми стандартних категорій і завантажувач JSON.
4. Щоб додати нову деталь, достатньо описати категорію і деталь у JSON. Щоб додати нову деталь з особливою логікою, достатньо написати клас і зареєструвати його у фабриці.
