## Як команди застосовувались у ЛР3

| Команда | Тімлід | Розробник | Тестувальник |
|---|---|---|---|
| stash | відклав чернетку ретроспективи (з -u), щоб перевірити гілку виправлення | відклав незакінчений завантажувач, щоб терміново виправити дефекти #29 і #30 | відклав експериментальні дані каталогу, потім повернув їх через apply, щоб перевірити виправлення |
| commit --amend | виправив номер задачі в повідомленні коміту | додав забутий файл CatalogQuery.cs | додав у коміт рядки плану тестування і змінив повідомлення |
| rebase | перебазував docs/lr3-retro на свіжу main | перебазував feature/component-catalog на main після виправлення, розв'язав конфлікт у JsonCatalogLoader.cs | перебазував свою гілку на гілку розробника, git сам пропустив уже накладені патчі |
| патчі поштою | отримав листом патч тестувальника до GitWorkflow.md і наклав через git am | надіслав листом два коміти (format-patch), наклав пропозицію тестувальника з листа через git apply | надіслав листами патчі з format-patch і git diff, наклав коміти розробника з листа через git am |
| cherry-pick | переніс виправлення в release/0.2 з -x і випустив v0.2.1 | взяв регресійні тести тестувальника у гілку виправлення | переніс два коміти з main, зроблені помилково, у свою гілку |

## Що вдалося

## Що покращити

1. Перед комітом дивитися git status: двічі в коміт не потрапив потрібний файл.
2. Створювати гілку до першого коміту, а не після.
3. Патчі з git diff створювати з параметром --output, щоб PowerShell не змінював кодування файлу, і надсилати їх лише вкладенням: у тілі листа пошта ламає рядки.
